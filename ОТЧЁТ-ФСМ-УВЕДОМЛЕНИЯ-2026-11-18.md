## 3 · «ВСЁ И ВСЯ НА АВТОМАТ» — постоянный FSM-автопилот

- **Автомат:** `scripts/notifications_fsm.py` — состояния S0 SCAN → S1 TRIAGE → S2 CLOSE → S3 VERIFY → S4 DONE; из S3 при остатках → S0 (дожим); максимум 4 раунда — **гарантированная остановка**.
- **Алфавит входа:** нити GET /notifications (unread + read-not-done).
- **δ детерминирована:** TRIAGE(нить)=KEEP только при `review_requested` от живого человека (не `[bot]`) — остаётся Хозяину; всё прочее (ci_activity, dependabot[bot], github-actions[bot], state_change, comment,_CHECK_RUN) = CLOSE.
- **Идемпотентность:** повторный DELETE = 404 = успех; леджер append-only (`notifications_fsm_ledger.jsonl`), state (`notifications_fsm_state.json`) накапливает счётчики.
- **Такт:** `.github/workflows/notifications-fsm.yml` — cron `*/30` + `workflow_dispatch` (с `dry_run`), секрет `HIVE_TOKEN`, SHA-пин checkout v7.0.1 (домашний канон), concurrency-группа, коммит леджера `[skip ci]`.
- Итог: инбокс математически не может удержать нити дольше 30 минут, кроме человеческих review_request.
