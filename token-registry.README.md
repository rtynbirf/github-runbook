# token-registry.json — схема реестра ключей

Реестр — единственное место учёта ключей роя (П-74, github-runbook). JSON не
позволяет ключей-комментариев, поэтому описание полей живёт в этом файле.

## Верхний уровень

Объект с ключом `entries` — массив записей. Сейчас реестр пуст: `{"entries": []}`.
Читатель должен также принимать вариант, когда верхний уровень — сам массив записей.

## Поля записи

| Поле | Тип | Смысл |
|---|---|---|
| `label` | строка, непустая | человекочитаемое имя ключа |
| `kind` | enum | `classic` / `fine-grained` / `app` |
| `scopes` | массив строк | фактические скоупы; для fine-grained — перечисление репозиториев и прав |
| `expires_at` | `YYYY-MM-DD` или null | дата истечения; null допустим только у `app` |
| `rotated_at` | `YYYY-MM-DD` или null | дата последней ротации; заполняется при замене |
| `note` | строка | владелец, назначение, что с ключом делать |

## Пример записи (иллюстрация схемы; НЕ добавлять в реестр без решения Хозяина)

```json
{
  "entries": [
    {
      "label": "fine-grained wave5 committer",
      "kind": "fine-grained",
      "scopes": ["contents:write в одном репозитории"],
      "expires_at": "2027-02-07",
      "rotated_at": null,
      "note": "единственный человеческий ключ; отзыв после волны ×5"
    }
  ]
}
```

Часовой `tools/token_expiry_watch.py` читает этот файл и по `expires_at` считает
дни до истечения: ≤ 7 → 🔴 (exit 1), ≤ 30 → 🟡. Полный список машинных приёмок —
в `ТОКЕН-КОНВЕРТ-2026-11-09.md`, раздел 5.
