# 06. Порядок: теги, бэкапы, правило «всё в репе»

## Теги — точки возврата

Тег = кнопка «откатиться сюда без размышлений». Ставится на каждом осмысленном состоянии:

```bash
git tag -a v1.1.0 -m "v1.1.0: быстрый старт + настройки узла в попапе; тесты 28/28"
git push origin v1.1.0            # или --tags для всех
```

Именование: `vМАЖОР.МИНОР` — МАЖОР меняет контракт (манифест, схему), МИНОР —
добавляет/чинит внутри контракта. Суффиксы допустимы: `v1.0.0-mv3`.

## bundle-бэкапы — «репа на случай смерти репы»

GitHub теоретически смертен (DMCA, блокировки, сбой). После крупных слияний:

```bash
git -C /путь/к/репо bundle create ../репо.bundle --all
# восстановление из bundle:
git clone репо.bundle восстановленный-репо
```

Хранить бандлы — вне песочницы (у владельца; локальный каталог загрузок/архивов).

## Ритуал конца сессии (для человека и агентов)

1. Все изменения закоммичены и **запушены** — рабочая машина ничего не «помнит».
2. Теги на осмысленных точках; bundle после больших работ.
3. Токены удалены (`rm -f /tmp/.ghtoken /tmp/.ghhdr /tmp/.gitcreds`).
4. В чате — краткий итог: что сделано, коды ответов, что осталось.

## Правило «всё в репе, не в песочнице»

- Песочница (временная машина агента) — **расходник**: умирает между сообщениями.
- Репозиторий — **дом**: история, теги, документация, вопросы (Issues).
- Всё, что должно пережить сессию, обязано быть коммитом. Черновик в чате — не память.

## Структура аккаунта (принцип, 01.11.2026)

Аккаунт общий: человек + несколько агентов. Договор:

1. **Каждому делу — своё репо** с осмысленным именем и описанием.
2. **Чужие репо не трогаем**: не меняем visibility, настройки, ветки; даже «улучшая».
3. **Общие правила общения с git** — см. `03` (fetch → ff-only → merge; без force-push).
4. Этот ранбук — общий стандарт настройки: новое репо приводится к нему за 15 минут.
